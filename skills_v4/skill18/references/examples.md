# OP-01 Reference

## Decision Variable

- The key variable is which of 4 patterns (A solo-for-other / B
  shared-hybrid / C explicit-flip / D pursuing) the case fits.

## Route Signal

- Use this skill when the actor must take an ACTION (gift, venue,
  plan, response) for or with another party with diverging or shared
  preferences.

## Hard Boundary

- If the task is what to SAY to convince the other, route to
  `skill13`.
- If the task is "what does X do NEXT" with several time-ordered
  commitments competing, route to `skill21`.

## Shortcut To Avoid

- Do not skip the pattern classification.
- Do not always default to "yield to the other party".
- Do not pick a single-world option in Pattern B (couple / common
  memory).
- Do not pick a private / solitary option in Pattern D (pursuing).

## Common Failure Modes

- Treating every other-preference item as Pattern A by default.
- Missing Pattern B's "common memory" / "couple" / "celebrate
  together" cue and choosing a pure single-world option.
- Missing Pattern C's "this time I want what I want" flip.
- Picking the bland "promise to do X another day" postponement.

## Minimal Pair

- Case A (Pattern A): X invites Y for Y's birthday → use Y's
  preference.
- Case B (Pattern B): a couple celebrate their anniversary → hybrid
  that combines both worlds.
- Case C (Pattern C): X has yielded for years and tonight insists →
  X's preference wins.

## Boundary Stress Test

- `Where will Sara take Lily for Lily's birthday?` → this skill,
  Pattern A.
- `What gift should the pianist give to her athlete partner for their
  anniversary?` → this skill, Pattern B (hybrid).
- `What should Xiao Ling say to convince Xiao Ting to pet-sit?` →
  `skill13`.

## Generalization Note

- The transferable core is decision-tree action prediction in social
  dyads: the right rule depends on the activity TYPE, not on a single
  global "be nice to the other party" heuristic.
