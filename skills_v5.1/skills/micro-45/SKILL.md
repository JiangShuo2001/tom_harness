# Trust and Reputation

## Use When
- Use when the question asks how reliable a person is based on what they have done before.
- Use when past promises, follow-through, honesty, loyalty, or consistency across interactions determine the answer.
- Use when the task is to infer whether someone deserves trust in future dealings from interpersonal history.
- Use when the person's reputation is built from repeated social behavior, not from a single claim.

## Do Not Use When
- Do not use when the main issue is whether a statement, rumor, or document is true; that is source credibility or factual accuracy, not interpersonal trust.
- Do not use when the question is about blame for harm, fairness, role, identity, or group membership instead of reliability.
- Do not use when the scene is about apology, repair, or offense management rather than whether the person is trustworthy.
- Do not use when there is no prior interaction history and the answer must be based on immediate evidence only.

## Decision Variable
long-term reliability

## Trigger Checklist
- Is the question asking whether this person can be counted on in the future?
- Is there prior behavior that shows keeping promises, lying, helping, betraying, or staying consistent?
- Would a repeated pattern matter more than one isolated act?
- Is the judgment about the person as a relationship partner rather than about a single statement?

## Workflow
- Identify the person being judged.
- Collect the relevant interaction history: promises kept, lies, betrayals, help, consistency, or follow-through.
- Weigh repeated pattern over isolated exception.
- Judge whether the history supports future reliability in this relationship.
- If the question is really about whether information is true, exit to source credibility instead.

## Special Case
**Single good act does not erase reputation**: A one-time helpful act does not override a long pattern of unreliability unless the question explicitly asks for change in reputation over time.

Scene: A classmate has broken several promises, but once returned a lost wallet.
Question: Should you trust them with an important secret?
Answer logic: The decision variable is long-term reliability. One good act is weaker than repeated broken promises, so the trust judgment should still be low unless there is clear new evidence of sustained change.

## Boundary Exit Rule
- Exit this unit if the prompt asks whether a claim is accurate, because that is source credibility rather than trust history.
- Exit this unit if the main issue is harm, blame, or apology, because those belong to responsibility and repair.
- Exit this unit if the main issue is who has status, power, or group membership, because those are different social variables.
