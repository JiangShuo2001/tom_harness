# micro-56 Examples and Boundaries

## Decision Variable
the cause of the result

## Route Signal
Use this micro unit when the prompt asks for the causal source of an outcome, change, or event.

## Hard Boundary
- Causation is not the same as responsibility.
- A cause can be an event or condition, not just a person.
- Blame, fault, guilt, and apology are out of scope unless they are explicitly part of the causal question.

## Shortcut To Avoid
- Do not jump from 'who caused it' to 'who is bad.'
- Do not replace causal attribution with moral blame or legal responsibility.
- Do not infer intention when only cause is asked.

## Common Failure Modes
- Answering with the blamed person instead of the actual causal factor.
- Confusing cause with intent or motive.
- Treating an accidental cause as irrelevant because it is not blameworthy.
- Overextending into responsibility judgments or repair behavior.

## Minimal Pair
- Case: A child drops a cup because the table shakes when a truck passes. | Why: The question is about the cause of the drop, so the causal factor is the shaking table, not blame.
- Case: A person forgets a promise and the friend feels hurt. | Why: If the question asks what caused the hurt, the forgotten promise is the cause; if it asks who should apologize, that is a different unit.

## Boundary Stress Test
- If a person caused harm accidentally, can you still identify the cause without judging fault?
- If several events contribute, can you name the direct cause that the scene highlights?
- If the question sounds like blame, check whether it actually asks for causal origin instead.

## Generalization Note
This unit covers causal explanation across physical, social, and event-based scenes, but only when the answer variable is the cause itself rather than blame, intention, or responsibility.
